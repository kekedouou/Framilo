## 当前开发版体验入口

E36已在同一入口接入光标跟手、未就绪临时预览、未打开记录也预备标注帧及按RAM额度预缓存。本地自动验证与播放中缩略图定点复验已通过；真实Eagle体验另验，完整结果/限制见[E36报告](docs/experiments/E36/report.md)。临时画面只辅助拖动观察，松手及标注沿准确帧确认。

当前开发入口仍是plugin/manifest.json的“视频分析”。关闭旧播放器窗口后从Eagle重新打开MP4；未选择过播放方式时默认“帧内代理”，已保存的选择继续沿用。可在“设置 → 高级 → 播放方式”切换“帧内代理／JPEG序列”，点击“应用”后重新准备并保持暂停。无需重新导入素材。

播放器先核对原文件身份和整数PTS帧索引，准备当前位置后允许播放；后台继续向整片准备，暂停观看也能进行，不必先播放一遍。常驻复用的是播放解码器；当前代理生成仍按可取消的小段调用FFmpeg。代理与JPEG共用5GiB磁盘总预算，剩余空间不足128MiB时停止后台扩展；资源足够才可能准备完整片，不承诺所有时长都能整片留存。RAM沿现有用户额度保留所需画面，整片压缩代理保存在磁盘。

默认720p为有损预览，720p／1080p／1440p沿现有画质设置，不放大小源；原视频与永久标注格式不变。当前最多120,000源帧，约为60fps的33分20秒，控制消息上限6MiB。初始完整文件身份与PTS索引仍需核对；已进入会话后的未就绪拖动可用最高480×270临时图，独立Chrome合成CFR/VFR首图约121/88ms，松手后才切准确图，不代表所有源秒开或真实Eagle成绩。原生编码不支持时保留当前画面，光标仍可操作。下面MVP Beta说明属于冻结旧发行。

## 能做什么

- 自动生成或复用720p整段预览，普通播放与缓存拖动集成。
- 有声播放、空格播放／暂停、拖动时间提示；松手后停在目标画面。
- 上一帧／下一帧及【／】快捷键，显示实际当前／总帧数。
- 读取已有Eagle标注、点击定位，在当前帧添加文字标注。
- 显示当前视频受管RAM；512MB、1GB～10GB容量选项，默认1GB，记住设置。
- 磁盘缓存上限5GB，闲置一天后在下次载入清理，侧栏可清除其他视频缓存。

正式播放器没有性能测量或实验按钮。

## 环境与安装

需要Windows x64、Eagle 4.0 Build 22+及Eagle中的FFmpeg模块。已验证的Eagle运行时为Node16.17.1／Chrome108；用户不需要另外安装Node.js。本包不附FFmpeg或视频素材。

1. 从[本版GitHub Release](https://github.com/kekedouou/eagle-frame-analyzer/releases/tag/v0.1.0-beta.2)取得 `eagle-video-analysis-0.1.0-beta.2-win-x64.zip`；请勿把源码ZIP当作插件包。
2. 完整解压到D、E等非C盘的可写目录，保留 `native/` 等全部文件。
3. 在Eagle的插件开发功能中选择“载入本地插件”，选择包含 `manifest.json` 的整个文件夹，不选择ZIP或单个文件。
4. 在Eagle单选一个不超过30秒的本地MP4，打开“视频分析 · MVP Beta”，等待准备完成。

已有旧Beta入口时，先关闭旧窗口；若Eagle提示插件ID重复，先移除旧Beta注册再加载新目录，旧包先保留。不要向正在运行的旧目录覆盖文件或手动改缓存记录。

完整安装和使用说明见[插件使用说明](docs/beta-preview.md)。源码检出不等于可运行安装包；自行构建步骤见下文。

## 日常操作

| 操作 | 方法 |
| --- | --- |
| 播放／暂停 | 按钮或空格；输入标注文字时空格正常输入 |
| 找画面 | 拖动进度条，查看对应画面的时间；松手保持暂停 |
| 逐帧 | 按钮或【／】，英文键盘对应 `[`／`]` |
| 换视频 | 在Eagle选中新MP4后再次调用插件；只改变选择不自动换片，也可关闭后重新打开 |
| 标注 | 点击已有标注定位；点击“添加”、输入文字并主动保存 |
| 内存／缓存 | 展开侧栏对应区域，应用额度或清除其他视频缓存 |

保存标注会写入对应Eagle素材；不会自动删除。修改或删除已保存标注请使用Eagle原生界面，原生播放器已经打开时不保证立即刷新。

## 缓存和数据

缓存位于实际插件目录下的 `cache/`，完整及临时缓存均不回退到C盘。准备中关闭会停止任务并清理未完成缓存；完整缓存跨次保留，复用仍需校验和内存初始化，不承诺所有视频秒开。

容量选项内部按512MiB及1～10GiB计算，压缩图片池包含在总额度内，最多占1/8；侧栏用量包含当前视频受管图片、音频及在途预留。它不是整个插件、Eagle或GPU内存的硬上限。调整额度后保留位置、安全重新准备，完成后保持暂停；高档位并未全部实测。

闲置一天清理在下次载入执行；容量不足提前淘汰最久未用且未占用的缓存。“清除其他视频缓存”保护当前载入和其他活跃视频，不删除原视频、标注或设置。不能确认归属的异常残片会保留并报错，不应手动删除写锁来绕过保护。

## 已知限制

- 固定720p；面向不超过30秒的MP4，已有H.264、H.265、VP9及4K60代表样本结果，不保证所有编码参数、色彩或损坏文件均可用。
- 之前约30分钟的自动测试曾达到约1.508GiB插件集合内存，超过1.5GiB测试保护线；原因尚未完全确认。新短测通过不能证明长期稳定性或全部问题已消除。
- 已有视频的准备/复用和拖动表现会随内容、内存额度、磁盘及后台负载变化。测试中的画布提交速度不等于屏幕实际显示速度。
- 不提供原生播放器播放位置同步、1080p／2K预览、常驻秒刻度、完整标注编辑器或播放列表。
- 真正强退Eagle、任意磁盘故障、全部素材组合和高RAM档位仍有验证缺口。

## 开发与复现

保留同一Git仓库，正式实现位于 `plugin/`，历史原型位于 `prototypes/`，测试在 `tests/`。不要在发行包副本中开发。dist只作临时构建/验收，日常安装放仓库外的非C盘目录；远程附件核对后，本地只留最新发行ZIP及校验文件，规则见[文件管理计划](docs/development-plan.md#发行产物统一整理f-01f-05f-06f-072026-10-16-用户批准)。

使用Node16兼容源码及开发用Node运行脚本。在Windows、非C盘检出指定提交后：

1. `node scripts/build-task-host.cjs`：使用系统已有.NET Framework编译器构建本机守护程序，不安装软件。
2. `node scripts/check.cjs --without-prepared-host`：本地代码、模型、文档和入口检查，不运行媒体实验或写Eagle库。
3. `node scripts/package-release.cjs build`：从干净的已提交来源创建唯一白名单包，已有输出则拒绝覆盖。
4. `node scripts/package-release.cjs verify`：核对ZIP、校验文件、依赖和构建摘要。

本机素材、配置和原始证据不公开，媒体实验需单独配置及授权，不能从源码ZIP复现私人素材的运行。包内 `BUILD-INFO.json` 保存来源提交和逐文件SHA256；新编译器输出须重新核对，不承诺跨机器生成完全相同的二进制字节。
