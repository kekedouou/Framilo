## 这版包含什么

- 纯黑的视频优先界面、左侧功能入口、图标轮盘、可调整宽度的右侧记录栏，以及按源帧定位的时间轴与片段循环。
- 点击画面或空格播放／暂停，滚轮逐帧，横向拖动定位；文字与圈画统一编辑，记录按源帧展示缩略图。
- **代理模式**：原片就绪后可以播放，后台自动生成完整 H.264 全 I 帧代理（每一帧可独立解码），验证完成后按同一源帧切换。等待新帧时保留上一张已确认画面，等待中禁止基于旧画面新建标注。
- **JPEG 序列模式**：先准备整片图片序列，再播放与定位；已取消 30 秒限制，长视频首次准备可能较久，准备中可以切换模式。
- 720p／1080p／1440p 预览、有界 RAM 缓存与自动提前解压。高级设置保留统一「GPU 加速」及代理磁盘额度；GPU 支持和实际速度取决于素材与设备。
- 实时性能窗口显示当前等待阶段及资源占用；旧体验记录、标准测试、`report.html` 和代理条已退役。

最近修复包括热拖动／暂停时的提前解压、短长片拖动灵敏度、时间轴聚焦蓝框及原地长暂停后的续播等待。E-49 将原压缩音轨无损复制到有界内存，避免浏览器仅为取声音又恢复原片的高分辨率视频解码；代理格式与画质保持不变。

## 使用当前冻结版

运行环境为 Windows x64、Eagle 4.0 Build 22+及 Eagle 已有的 FFmpeg 模块。普通使用不需要另装 Node.js 或 Rust。

已经注册本仓库 `plugin/` 的用户，关闭旧播放器窗口后，在 Eagle 选择本地 MP4，再打开原来的「视频分析」即可。默认 720p、1 GiB RAM；设置 → 高级可切换「代理／JPEG 序列」，需要应用的设置应用后保持暂停。

本次发布的是 **Git 源码冻结标签**，没有制作新的安装 ZIP，也没有覆盖旧 Beta。GitHub 的源码 ZIP 不等于经过独立安装验收的插件包；新机器部署前应按下方开发验证核对原生文件和入口。

## 缓存与数据边界

- 原视频保持不变；主动保存、编辑、删除标注会更新相应 Eagle 素材，保留原有删除保护。缓存清理不删除原视频、标注或设置。
- 代理磁盘额度默认 5 GiB，可设 1～100 GiB；自动淘汰可确认归属且未占用的旧视频代理，保护当前源、活动读者与生成任务。单片超出额度时继续使用原片；JPEG 沿用独立的 5 GiB 缓存策略。
- RAM 默认 1 GiB，可选 512 MiB 及 1～10 GiB，统计受管理的解码帧、音轨、缩略图、在途预留等；它不是整个 Eagle 进程或显存的硬上限。
- 缓存和本机设置位于实际插件目录，不随源码标签上传。完整代理复用前仍要验证，不能承诺所有素材秒开。

## 已验证与仍有限制的部分

E-49 的本地回归、真实音轨验证及 Eagle 自带 Node 16 兼容检查已通过。同一 4K AV1／Opus 视频在独立 Chrome 中，长暂停后声音时钟恢复由约 406／682 ms 降到 94／143 ms；这是两个测试位置的结果，**不是 Eagle 实际窗口的验收，也不是零延迟承诺**。

该素材每次打开新增约 0.24～0.33 秒音轨准备、约 3 MB 受管 RAM，不新增磁盘音频缓存。非零音轨起点、不支持的格式或音轨超出预算时保守回退原路径，可能仍有原来的等待。其它编码、长视频及真实物理音画同步仍有验证缺口。

当前源帧上限为 120,000 帧，缺失或重复的源时间戳会明确拒绝；并非无限时长。原片冷跳、后台代理生成、磁盘与设备负载都可能影响响应。冻结用于保留当前可回溯版本，后续改动需另行决定，不覆盖本标签。

## 开发与复核

唯一正式实现位于 `plugin/`；原生桥源码和许可证维护在 [native/filmcraft](native/filmcraft/README.md)，运行使用 `plugin/bin/`，不依赖历史原型或 Rust 开发目录。

```powershell
node scripts/check.cjs --without-prepared-host
node scripts/package-release.cjs native-experience
node scripts/check-handoff.cjs --base HEAD
```

前两项分别检查现行源码／模型／文档，以及原生运行清单和许可证；不生成媒体、不写素材库，也不创建新安装包。真实 Eagle 操作与本地检查分别记录。历史 Beta 的 `build/verify` 配方只用于旧 Beta，不能直接用来发布当前原生版。

本次标签只包含已提交内容；本机原始证据、素材、偏好、缓存，以及既有 43 项未提交探针／退休文件均不包含在标签中。详细归属见冻结记录。
