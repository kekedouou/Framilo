# E-34 开发记录

2026-10-25用户批准持续开发，遇决策/必须亲自体验才停。当前已接入常驻WebCodecs播放与H264全IDR分段代理，JPEG保留可切换；本地45秒和5分钟的就绪拖动检查通过，首轮30分钟后台规模关失败，正在定点修复重复盘点关联，真实Eagle尚未通过，不称最终交付。

## 实现与模块

- avc-access-units纯流拆分，严格AUD/SPS/PPS/IDR及8MiB上限；不冒称其解析全部H264语法，实际像素由原生解码检查。
- proxy-decoder复用Chromium VideoDecoder，最多两项在途，必要时8ms后flush，输出ImageBitmap交既有Player/Canvas。硬件为prefer-hardware提示，未验证实际NVDEC；不安装新原生库。
- long-media在原源SHA/整数PTS索引上制作baseline5.1全IDR AVC，CRF20/ultrafast、8bit420、BT709；约2秒/最多120帧，仍逐帧比对原PTS，音频沿原分段PCM时钟。常驻的是播放解码器，后台制代理目前仍为可取消分段FFmpeg任务，没有假称整片单次连续转码。首片可播放后后台独立继续，不要求先播放一遍。
- cache/frame-pack明确videoEncoding=annexb-idr-v1+codec、数字.avc帧，复用原frames.pack/事务/哈希/身份/恢复/5GiB总账本；旧JPEG缓存不变。已验证派生段metrics.sourceSha256匹配当前原SHA时，“清其它”不删当前JPEG/AVC段。代理和JPEG不是各占5GiB。
- proxy-background前台优先、段提交后保留原租约及小型索引；所有代理压缩字节仍在磁盘，RAM只读所需帧。worker/client通过受guard核验的段描述增量接入，遥读清单逐字节一致校验没有放宽；窗口淘汰仅归还借用，最终关闭/换模式等待读取、解码及整会话租约释放，失败不虚报成功。128MiB磁盘余量不足停止背景扩展，不无限淘汰头部制造假完整。
- media-wire无损传整数PTS、共同时间基准与显式结束值，最多120000源帧、6MiB控制体，全帧索引另有64MiB上限。108000帧/30分钟60fps纯模型约1.22MiB，不丢帧或按平均帧率猜测。
- preferences增加可选playbackBackend，旧记录缺字段默认proxy，JPEG可选；统一应用后保持源SHA、当前帧/圈画坐标与循环状态。设置高级三级菜单承载播放方式及后台进度，无常驻toast。持久化读写、中断及旧入口模型分别验证。
