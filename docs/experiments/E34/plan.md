# E-34 常驻解码与渐进磁盘代理

2026-10-25用户批准尝试开发，遇到决策或必须真实体验时才停，持续到最终交付。沿用R-02/03/04与P-01/02/03/04及E33/decoder-review.md门槛。保留JPEG可选，新后端以同一Canvas/UI/标注/音频时钟装配，不改原素材与永久标注格式。

## 首关与实现选择

先验证Chromium原生WebCodecs VideoDecoder常驻实例 + H.264全IDR Annex-B帧内代理。每个access unit含SPS/PPS及IDR，最多两个解码在途，保留PTS独立索引与原SHA；复用现有FFmpeg，不安装额外运行库。不是ProRes，不套用ProRes容量/性能预算；硬件加速是可选偏好而非已生效结论。HTMLVideoElement seek不作为逐帧准确核心。若Eagle缺少能力或吞吐/颜色不满足，先查证并报告具体决策。

## 模块与格式

avc-access-units纯流解析、proxy-decoder复用原生解码器，Player只增加受注入的decodeFrame生命周期。后台复用cache的分段事务、frames.pack、预算、租约及原Windows守护；缓存manifest可选videoEncoding，逻辑帧为数字.avc，JPEG旧格式继续兼容。读写/恢复/清理/打包/模式偏好和关闭互切一起盘点，不伪装JPEG或借修改recipe规避旧数据。

索引超过当前24,000帧/通信体积时采用有界紧凑整数PTS传输，不能减少源帧。背景生成分段可取消，前台定位优先，完成段原子提交；额度不足停止后台扩展，原5GiB总预算不提高。首关通过后才进入正式默认设置与整片渐进准备。

## 验证与证据预算

新现场verification-runs/e34-proxy；第一关最多4轮、每轮512MiB/十分钟/单源生成进程，证据8MiB，合成素材、现有FFmpeg与Chrome，禁止真实库写入。先核对Annex-B格式、实际VideoDecoder单帧输出、乱序独立解码、像素/帧身份、P95和取消关闭；未完成首关不扩大长片媒体预算。默认模型不生成媒体。Eagle实际能力与体验独立核验，Node16命令行/独立Chrome不能替代。

首关通过后按当前实际瓶颈单列有界长片对照预算，采用30秒与5/30分钟同素材同动作，区分已解码/磁盘代理/未生成区域，记录全部请求、过时数、最长无提交、最终目标、缓存/CPU/GPU/音频/内存。自动不合格先修复，不把小修逐次交用户陪测；需要真实Eagle人工观察时集中一次。

## 完成条件

既有P95≤50ms拖动目标保留；50～100ms登记差距，超过100ms不能算同等流畅。RAM窗口与就绪代理范围分别测，未生成区明示等待。默认检查、handoff、文档影响正文、整理与本地Git齐备；不推送，保留三个既有外部Git界面探针。

## 正式集成与长片规模关卡

首关原生解码已通过，正式集成脚本的硬预算为verification-runs/e34-integration最多6轮、每轮512MiB/十分钟/证据总8MiB，现6轮已用完并封存。该预算先写进脚本，文档本节在集成后补录，属于记录滞后，不伪造先行记录。中间失败、取消收尾问题、控制消息标记错误与证据大小失败全部留存；第三轮无原始统计不能声明通过，单列evidence-overflow回执。

新增独立长片规模现场verification-runs/e34-long，最多3轮、每轮2GiB/二十分钟/一个生成进程、证据总8MiB，先30秒同脚本基线、再5分钟、最后30分钟60fps（108000源帧）；源由2秒合成片段stream_loop复制延展，性质为索引/缓存规模验证，不当复杂素材编码吞吐。只有既有正式集成SSD P95≤50ms与RAM拖动通过才可跑最长场景。脚本原子写状态、身份/哈希清单与失败证据后清理，不覆盖旧预算或自动增额。真实Eagle无现成调试通道，不擅自重启宿主；本地关卡完成后集中人工验证实际Chrome108能力及体验，这是用户允许的停顿点。

代理会话保留已提交段的原租约与小型索引，不在RAM保留整片压缩/解码图像；仍由同一5GiB缓存账本保护与停止背景扩展，关闭/模式互切等待读取结束并释放全会话，避免每次跨段重走写事务。新增metadata是有界段描述与≤120000源帧表，renderer/worker/浏览器内部内存另记，不伪称缓存额度是全进程硬上限。

## 规模缺陷的定点修复验证（2026-10-25追加）
