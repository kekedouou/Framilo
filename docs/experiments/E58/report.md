## Causes and fixes

1. Cold release→play reused the pending native target, superseding the original seek Promise. UI only released its cursor intent after that Promise succeeded, so playback advanced while the cursor stayed at the old target. The UI now hands ownership back when playback owns the clock or the exact paused target arrives, independently of that Promise. Active/newer gestures, pending targets, held images, source epochs and failure protection remain. No frame/clock mapping or decoder changes.
2. Startup had no early render opportunity before synchronous module/session initialization. HTML now contains preparation copy; app captures the selected source first, then UI publishes preparing and yields a paint boundary before heavier initialization. Close resolves/cancels this wait and drains the initializer; reopen cannot revive old work. This provides early feedback, not a claim that all setup finishes faster. Empty/unsupported/error states still replace preparation normally.
3. Capacity decisions now hide secondary proxy progress while its state/lifetime continues updating. Choice removal restores the current message, not an old timer; ordinary results still fade and persistent save/cleanup errors are not cleared.
4. Named Thor4K source is77.461s/4642 frames,3840×2160 H264 with zero-origin44.1kHz AAC,170,279,943 bytes; source hash matches the old E44 identity. Audio copy was rejected first for final packet boundary, then for three copied packet-duration labels, causing `native-player` to fall back to HTMLAudio reading the full video. This is a verified player compatibility limitation triggered by the file's packaging, not evidence the file is corrupt or that every delay is caused by it.

The copied fragmented AAC has the same packet bytes, PTS/DTS, stream config and audible track boundary, but full1024-sample duration labels replace three shorter presentation intervals and extend10 samples past the declared track end. `native-audio` now normalizes **only copied, bounded AAC** to exact neighboring PTS/declared end before comparing against the unchanged source fingerprint. Source tail remains strict; non-AAC/oversize blocks, altered payload/PTS/DTS/end/config or source changes still fail safely. Internal receipt exposes adjustment counts. No encoding/audio quality change or persisted format change. Original source and copied audio independently decoded to PCM have identical hashes.

Actual player/reader checks now use the1,263,959-byte (~1.21MiB) verified original-audio copy via Blob for this file under both CPU/GPU. This removes the identified full-video audio fallback from resume. Browser audio seeking/listening in Eagle was not measured here; real latency improvement remains user acceptance, not a timed guarantee.
