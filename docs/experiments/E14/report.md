# E-14：实施与验证记录

2026-10-22，基线df7e7cb。[批准范围](plan.md)。同一plugin本地实现完成，**尚未获得本轮真实Eagle集中体验**。

用户反馈：E-13高倍速报错已解决；高倍速播放仍卡顿，打开后左右拖动曾暂时失效，R选区希望画面拖动，1080p错误显示2K。用户批准右键观看/圈画菜单及高倍速连续播放优先，圈画菜单排除滚轮可调属性、顶部工具条默认收起。

## 原因与实现

E-13高倍速仍沿JPEG逐帧读/解码，供帧不足会暂停时钟和声音等待，属于可导致停顿的已知策略；真实素材卡顿各因素占比尚未计量。Eagle原生8倍速流畅是用户观察，不宣称已测其丢帧比例或硬件解码。

1. **拖动暂时失效**：复现到UI在seeking时允许时间轴却禁止画面启动拖动的差异；另补同一鼠标丢失up/cancel后新down立即清旧状态，防止等到一次无按键move才恢复。两条均有回归，但没有捕获用户那一次真实事件轨迹，不能把它唯一归因为其中一条。
2. **高倍速连续优先**：高于1倍速继续原音频/播放时钟，选择当前时刻之前最新已准备好、在同一循环轮次不倒退的画面。已开始的快放读取可以完成并进入原有界池，避免目标不断前进时每次慢读都被当过期丢弃。1倍速仍保留150ms缓冲保护，手动暂停/定位/逐帧和最后一帧仍精确；两图像任务、RAM/磁盘和颜色不变。已实际遇到的损坏解码仍报错，跳过而未读取的资源不声称已逐张验证。启动仍有原预热，低供帧时画面更新率依然受解码能力限制，不能据此承诺达到原生播放器的真实流畅度。
3. **R画面选区**：同一loop-selection接收画面水平输入、先头后尾/已有端点调整；选区中不调倍速、不单击播放。R松键先结算画面末次输入再确认，Esc/失焦/换源沿旧取消保护；时间轴仍可用，提示同步说明画面操作。
4. **右键菜单**：context-wheel只负责输入/DOM，UI复用既有选区/标注/圈画/循环操作。观看上标注、右循环、下圈画、左片段；短点无动作，甩动/长按后方向选择在松开时执行，回中心/Esc取消。圈画六工具/颜色/更多，更多含撤销、删除选中、保存/退出、临时显隐和显示原工具条；尺寸继续滚轮。原工具条默认收起，未知保存/输入法/未存退出确认不绕过。菜单靠边移位后长按按可见位置选择；短甩仍按起点方向。抬键、按钮丢失、失焦、换源、销毁均取消旧动作，120次模型开关未增加保留监听器。
5. **画质过滤**：按保比例、不放大的实际显示尺寸去重，包含旋转与SAR。1080p只显示720p/1080p、较小源只留首个有效档位；只有一个可见原始分辨率标识。全局记住2K遇到1080p时显示1080p但不默改偏好，后遇4K恢复2K；点击应用才保存有效档位。仅过滤UI，不重写旧缓存或永久数据。

## 失败与修正

新增UI测试首次在尚未实现的previewChoices处失败，保留原输出；不是借此证明全部真实故障已复现。快放不再缓冲后旧70tick断言先到视频尾，最后帧再step不能+1，改为在视频中段检查并另保留末帧规则。损坏帧测试最初指定一个可能被快放跳过、根本未解码的帧，改为明确提交该损坏解码，再验证错误不被隐藏。浏览器删除用例初始误以为此前只有一个对象，现按选中项减少一条、撤销恢复并保全其他对象断言；失败原输出保留，不作为产品故障/性能下降。
