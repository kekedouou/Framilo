## 修改与原因

1. “2026-10-28（2K+TSR）”源2688×1024，三档预览高度487/731/975均为奇数，原whole-proxy要求偶数导致失败。现编码补至488/732/976，SAR恢复原比例，正式读者仍准确输出原1280×487、1920×731、2560×975。既有偶数代理缓存身份兼容；奇数新增显示几何参与identity，不拿错误比例旧资产复用。
2. 原生每次play串行等待最多4张邻帧，JPEG等待当前和后续3张，之后原生还重复等待音频seeked。已移除启动前邻帧阻塞，最终寻帧并行预定位音频，暂停续播复用有效音频位置。暂停立即停声/时钟并取消前台读取，JPEG精确落帧后台对齐；后来play/seek优先，迟到audio.play不能重启已暂停声音。
3. 左键轮盘拖动改源帧累计，默认8 CSSpx/帧、Shift 4px/帧、Ctrl 16px/帧，同时按默认；窗口宽/总时长不参与。UI传入session.loopFrameAt，VFR用实际ordinal映射，不以平均FPS猜时间；支持循环边界和修饰键切换不跳变。
4. 高级GPU加速单开关默认开，原独立编码/解码/绘制控件移除。偏好新bool优先旧字段，保存/重开派生值一致；明确NVENC不可用时清该次GPU事务，按CPU配方/新key重试一次，不吞源或额度错误。GPU绘制不降低分辨率；代理编码有损，CPU/GPU不宣称等画质。JPEG沿既有序列准备策略。
5. 其它缓存清理由后台guard/task-worker执行JPEG安全删除，whole代理按租约/归属异步分项盘点清理；独立whole不反复全量计入JPEG5GiB。UI先显示忙碌提示并禁重复，随后显示释放量；关闭等清理屏障。当前源/占用/未知文件保留。
6. 播放方式显示代理/JPEG序列。代理自动生成，去掉自动/生成/取消控制；提前解压固定true，旧false读取/保存/运行均迁移为true，设置中不展示。底层生命周期的取消/释放能力保留。
7. JPEG初始准备在左下显示真实阶段和已生成帧数，完成后撤除；无可靠总量不猜百分比。
8. 设置/工具条/缓存清理反馈统一左下，与面板分离。成功约2200ms后渐隐，重复同文本通过消息序号重新计时；错误/未保存/未知与进行中状态不淡出。修复了相同文案手动解除faded但不再建timer的潜在常亮问题。
