# E43 交互取图与持续代理解耦

2026-10-28用户批准“开始”，承接E42架构复核及预期成果。关联R-02/R-03/R-08、P-01～P-04。涉及源寻帧、解码、调度、缓存，必须进行同源性能验证；先隔离验证，再接正式。不接受基准、不提交或推送既有积累。

## 实施顺序

1. 优先验证已有WebCodecs原生解码器直接读取源MP4压缩包的路径：ffprobe取得可核验包位置/PTS/关键帧/编码初始化信息，独立读取与解码，避免交互先生成代理。仅对已验证格式启用，未知能力回退，不能丢失源PTS或借近邻图保存标注。若需要新增原生依赖，先明确代价再决定，不静默安装。
2. 轻量预览独立供图、最新意图优先、按处理能力选择有价值画面；已在缓存中优先返回。正式画质、JPEG模式、标注数据和源文件不改。
3. 全片代理连续推进，保留分段存储；生成器复用/逐步发布先经过取消、关闭、旧缓存及源身份关。前台和后台总资源有界，不因增加并发失去安全边界。
4. 固定视频/工具SHA和路线，记录冷首图、快拖新图间隔/时间偏差、松手准确帧、全片推进、CPU/GPU及资源。不同原型失败也保留事实，不以源码存在当性能通过。

## 本轮隔离验证预算与边界

只读E42同一4K源与现有FFmpeg工具。verification-runs/e43独立目录，累计生成物≤2GiB、单轮≤10分钟；不借用E42已消费预算。新工具只写项目内证据，不重跑历史重置入口、不修改Eagle安装/素材库。临时媒体/浏览器资料验证绝对路径、归属、非链接与内容后清理，保留有界原始证据。

沿用低清P95≤200ms、准确帧P95减半的目标；已覆盖轻量预览争取P95≤50ms、快拖新图间隔≤100ms。冷启动与预热分开，未达到必须说明差距。独立Chrome不冒充Eagle；结束前更新文档、适用检查、真实分析和报告。必要架构取舍或宿主体验不足集中说明。

## 2026-10-28已批准的视觉取舍与接入范围

用户在同源画面对照后明确接受：480×270（竖片对调）、约8～10张/秒，仅用于快速拖动。松手、慢拖、逐帧和标注仍走准确源帧，不能把稀疏图当成最终图。实现速度门槛为源时间移动超过3秒/实际秒且final=false，首个输入不推断为快速拖动。

直接源包WebCodecs冷跳未通过200ms关卡，不接入正式。采用独立稀疏JPEG供图：连续最多15个原分段的源窗口，管道读图与原单写入队列分离；仅完整验证的小段发布为缓存。首个准确段就绪后先覆盖低清，再恢复完整代理的闲时生产；用户准确帧请求始终可插入，最多一个低清生产器及一个原准确生产任务。64MiB低清磁盘上限计入原5GiB账本，达到预算停止新增，未覆盖位置保留原生回退；不冒称任意长片全覆盖。

渲染仅一个读取/解码在途和一个最新待处理意图，稀疏位图≤4MiB（亦受RAM额度约束），输入中转预留2MiB，画布最多480×270 RGBA；所有像素资源计入现有RAM预算。缓存版本单独标识，旧普通画质/序列缓存不重写。取消先停生产，再排空读取/归还租约，最后释放源。
