# E44 原生路线体验版交付记录

2026-10-28：已按用户连续开发授权接入正式 `plugin/`，可从现有“视频分析”入口体验。真实Eagle已加载正式媒体、播放器和绘制模块完成三轮固定轨迹。**这是开发体验版，未完成全部E44验收，未替换冻结Beta。** 关联R-02/R-03/R-08、P-01～P-04，验收线沿用[重建计划](plan.md)。

## 怎样体验

1. 关闭旧“视频分析”窗口，在Eagle选择MP4，重新打开原来的“视频分析”。现有注册目录仍为本仓库 `plugin/`，无需重新导入素材或安装Rust。
2. 建议先用720p、默认1GiB体验。已有“帧内代理”设置现在进入原生链路；JPEG仍是独立整片序列准备模式，不再限制30秒。
3. 原片首帧准备后可播放、拖动和逐帧。自动整片代理默认开启；旧偏好保留。完整代理校验完成才在同一源帧接管。按最新用户决定，同源等待保留上一张准确画面，新帧确认后替换；光标保持最新位置，等待/失败保留状态禁止新建标注。新源首帧前隐藏，避免跨源残留。
4. 设置保留CPU/NVIDIA代理生成、播放解码偏好、RAM与画质；增加自动整片代理、手动生成/取消和GPU视频绘制。GPU编码、解码、绘制互相独立，实际硬解以运行记录为准。

正式缓存仍为5GiB，旧资产与新整片代理合计。此机旧缓存已接近上限，空间不足停止生成并继续原片，不擅自删除现有资产。缓存清理由用户主动调用。原素材和永久标注不属于缓存。

## 当前运行链路

- native-backend负责只读源身份、异步packet索引、后台任务和读者所有权；源帧使用整数PTS，缺失/重复时间明确拒绝。
- native-reader/native-wire负责有界进程协议、取消及实际PTS核对；关闭等待stdio排空和进程回执。
- native-player负责播放、源帧、原音频时钟、RAM邻域帧及缩略图租约。目标独立于旧画面，旧完成回调不得拉回新位置。
- native-renderer将兼容YUV420p传给WebGL准确转换；关闭GPU或不可用时CPU转换，其它格式走RGBA，没有第三条低清链路。
- whole-proxy独立生成一个完整H.264全I帧MP4，CPU CRF20/ultrafast或NVENC QP20/p1。帧数量、PTS映射、独立帧、尺寸及哈希全部核对才原子发布。中间片段不对前台开放，CPU/GPU不宣称等画质。
- app/session接用现有UI、时间轴、圈画、记录和设置。原分段/稀疏低清不在原生模式运行；JPEG所需共享任务、缓存、安全和导出模块保留，不能按文件名整份删除。

## 尚未通过的完整验收

1. 实际Eagle加载正式媒体模块的隔离计量入口；常规“视频分析”完整UI、真实标注写删、草稿关闭、记录与轮盘仍需集中体验。本轮未执行新的素材写删。
2. 原片+后台生产争用三轮、快拖新图间隔、空白等待统计、物理音画同步未补齐，不能从光标成绩推断通过。
3. 固定短样本之外的编码/音轨、长片、1080p/1440p、HDR和30分钟稳定性没有全矩阵验收。
4. 90°旋转同时非方形像素可能明确拒绝。YUV快路限兼容8位C420、无alpha及BT709/sRGB传递特征，其它准确RGBA回退，不是任意素材零拷贝。
5. 原片冷跳仍须从关键帧前滚，可能慢于完整代理；超过5GiB无法整片留存。不能用无限缓存、延长超时隐藏差距。

复盘：复用原生源码并在真实宿主跑固定轨迹，将输入、原片解码、完整代理和像素传输分开，才得到可量化改善。曾把局部通过推断整体可用；当前把模块实测、退出与最终体验分开登记。
