## 1. 用户需求与澄清

1. 放弃分段按需代理及480×270稀疏补位方案，先把普通播放器级的直接播放/拖动做好。保留现有UI、标注、轮盘、片段、记录和数据保护。
2. 打开原片后无需等待代理，可直接播放/拖动；前台使用可用的硬件解码、GPU视频绘制及有界RAM缓存。拖动只解码，不触发编码。后台另启动一次整片代理生产，不跟随鼠标位置重启。
3. 目标未解码时光标仍跟手，画面区不显示冒充目标的旧图/近邻低清图。原提案采用暂空；2026-10-28用户明确改为等待时保留上一张准确画面，新帧确认后替换，等待或失败保留时不允许新建标注。实际出图前不更改当前已确认源帧身份。慢拖/逐帧利用附近缓存和准确解码。
4. 代理保留每一个源视频帧及其时间映射，不固定抽成8～10fps。快速扫过10秒不代表必须依次显示这10秒的全部帧：显示刷新时只处理最新有效目标，丢弃过时输入，不能排队补播。
5. 整片代理完成并验证后提示，在同一源时间切换；拖动/编辑过程中延后切换到安全边界。停止或播放状态、音频时间、标注坐标不变。失败继续原片，不把半成品当可用代理。
6. 增加硬件编码、硬件解码、GPU视频绘制、自动生成代理、代理路径/占用/清理及RAM额度设置。显示实际支持/使用/回退状态，不用一个“GPU模式”混淆三类工作。
7. 保留JPEG序列作为独立手动模式，沿既有整片准备策略，不把它插进新默认链路；如果以后想删除此模式另作产品决定。

“一开始全部准备好且不等待”不能同时保证：全帧解码/编码本身需要时间。建议原片立即可用，同时后台自动做全片；再次打开命中已完成代理可直接使用。每分钟60fps的1280×720 RGBA解码图约12.36GiB，1920×1080约27.81GiB（不含其它占用）；因此全片放磁盘，RAM只保留有界邻域，不能全部塞RAM。保存每帧不等于所有帧始终驻留RAM。

## 3. 新架构：两条工作流，一个前台显示出口

```text
鼠标/快捷键 → 最新目标源时间 → 前台播放器 → RAM附近帧 → 视频绘制
                                  ↑
                 原片 / 完整且已校验的代理（二选一）

打开视频 → 独立后台整片任务 → 临时代理文件+源帧映射
                              → 完整校验 → 原子发布 → 同帧切换通知
```

### 前台播放器

- 常驻读者/解码器，不在每次寻帧启动FFmpeg，不等待后台生产锁。前台输入最多一个有效在途意图及一个最新替换；旧结果可安全排空但不得覆盖新目标。
- 原片和代理共用同一播放器接口、时钟、源帧身份、缓存与显示逻辑，只切换输入资产。先读取附近缓存，再最小范围寻帧/前滚解码。取消废请求不等于每次清空全部已用缓存。
- 有界缓存按方向保留前后帧；CPU内存与GPU纹理分别计量，不能把两份占用当一份。音频只有一个时钟/输出，不能在切源时同时播放两条音轨。
- 不沿用“失败时再套原生video、稀疏JPEG、分段代理多层抢画面”的链路。可用解码后端在打开源/切设置时选择一次；有明确回退原因，不对每次拖动不断换后端。
- 代理未就绪时不承诺任意原片远跳零延迟；长GOP仍有前滚代价。源映射可用前不开放逐帧保存/标注，避免先按估算帧率写数据。

### 独立整片代理任务

- 一个源一次从头到尾转码为一个完整代理资产，鼠标目标不进入生产器。允许有界磁盘I/O缓冲，**不再按片段生产、领取片段租约或边拖边造片段**。
- 原片首屏不等待代理。后台有明确进度、生成速度、剩余时间估计、暂停/取消/失败/完成状态；失败或预算停止绝不表现为“无声卡住”。进度来自已处理源时间，不用虚假定时增长。
- 建议第一候选为整片MP4 + 全帧内H.264（每帧可独立解码）、保留源帧时间映射。继续使用现有FFmpeg/NVENC能力，不直接更换HEVC/AV1/ProRes或安装依赖。完整代理必须验证帧数、时间映射、首尾、旋转/SAR/色彩、音频时钟和可随机访问性后发布。
- 不宣称沿用相同CRF/QP数字就等画质；第一关同时给出火花/烟雾同帧对照、整片耗时、磁盘和真实拖动结果。全帧内通常占用更大；高画质参数未通过前不定默认配方。暂停转码不一定释放GPU上下文，取消/关窗释放；第一版中断未完成文件允许下次重新生成，**不假称可续传**，已完成代理可复用。
- 原5GiB总磁盘额度先保留，预估和实时监控；不足则停止/提示并继续原片，不能偷偷删旧有效记录、提高上限或发布半片。只清本任务所有权确认的临时文件，失败诊断保留有界摘要。更换代理目录先验证可写、空间和现有活动任务，不隐式搬走原素材。
- 后台与前台独立生命周期/消息通道；前台关闭不排在转码队列后。取消有完成回执，退出现有看门狗是最后保护而非正常流程。后台争用资源时先降并发/限速；不能因持续拖动反复从头生产。可见“暂停”与系统自动减速区分。

### 第一技术关：先确认轻量后端能胜任

不得把“常驻”当成已解决。E43直接源包WebCodecs已有0.6～1.6秒冷跳失败证据。批准后先在真实Eagle测最小直接播放样机，以同宿主原生video为普通播放器参考，核查WebCodecs可控解码/绘制能否达到相近响应并保持源帧身份、音画和关闭正确。

若现有浏览器能力无法提供可控软/硬解、低延迟且准确的统一路径，停止接入，提供单一原生播放内核的包体/许可/维护/部署代价再决定；不叠第三条预览链路。此计划不包含静默安装新原生组件。源码可借鉴mrv2的常驻读取/方向缓存及FilmCraft的独立代理任务；不能以引用竞品代替本宿主验证。

## 4. 设置提案

| 设置 | 作用与边界 |
| --- | --- |
| 硬件加速编码 | 仅后台代理生成；关闭使用CPU。缺少对应设备/编码器时说明不可用或回退，不能假勾选 |
| 硬件加速解码 | 前台播放与寻帧；后台源解码可遵循该选择但分别记录实际路径。关闭请求软件；若宿主只能提供偏好，明确显示“偏好/未确认”，不称强制关闭成功 |
| GPU视频绘制 | 选择本播放器可控的视频绘制路径；不是关闭Eagle整个界面/Chromium的硬件合成。无法实现可靠软件路径时禁用该切换并说明，不做假按钮 |
| 自动生成整片代理 | 建议开启，打开源后后台生成；关闭仍可直接播放，保留手动生成/取消入口 |
| 代理画质与位置 | 保留现有画质档位，显示文件夹、占用、进度，清理须避开正在读取/写入的资产 |
| RAM额度 | 附近解码帧的有界缓存，非整片/整机RAM承诺 |

不直接照搬含义不明的“智能优化”。若保留自动策略，必须明确为前台优先、后台限速、有界缓存，报告能说明实际发生了什么。GPU编码、解码、绘制互相独立，不设置成一个总开关。

技术依据：NVIDIA区分NVENC编码与NVDEC解码，官方亦说明短独立任务的初始化开销；WebCodecs的硬件加速项是偏好提示，不保证宿主一定执行。最新版规范不证明Eagle Chrome108支持全部能力，必须实测。
- [NVIDIA FFmpeg硬件加速与性能指南](https://docs.nvidia.com/video-technologies/video-codec-sdk/13.1/ffmpeg-with-nvidia-gpu/index.html#performance-evaluation-and-optimization)
- [W3C WebCodecs硬件加速语义](https://www.w3.org/TR/webcodecs/#hardware-acceleration)

## 6. 自动测试和报告

先固定现有77秒4K样本SHA、工具/驱动/宿主版本、画质、RAM、窗口/刷新率、编码配方、后台状态；记录CPU/GPU温度/占用，异常外部负载的轮次单列，不挑更快结果。

测试四类状态：原片且后台关闭；原片且整片代理正在生成；完整代理磁盘冷读；解码帧RAM命中。每种至少3轮，固定快拖、慢拖、反向、远跳、停顿/松手及同帧轨迹；CPU/GPU交替执行减少先后偏差。正式UI与宿主能自动驱动则直接驱动；若缺少实际Eagle自动控制能力，独立浏览器仍单列，集中安排一次真实宿主体验，不能冒充端到端验收。

报告只需突出：光标跟手、最新目标到出图、空白等待总时长/最长一次、快拖每秒新图、松手准确帧、整片代理生成时间、磁盘/RAM/显存峰值、错误次数。被替代、取消、超时、失败都有分母，不只统计成功请求P95；CPU/GPU编解码实测路径和未确认项可展开。整片完成时间不只推算前12秒。

先同一素材达到目标，再验证既有10秒/1分钟/10分钟/30分钟样本（若现有授权素材缺档先登记，不擅自造/导入）、1080p/4K、30/60fps、可变帧率、旋转、不同音轨与无音频。保留原手动标准入口用于核对体感，新架构另立测试组，不覆盖旧基准。

开发实验建议新增独立目录`verification-runs/e44`，累计生成≤2GiB、单轮≤10分钟；该额度须随本计划批准才启用，现有2GiB E43不复用。长片超出这轮预算时只登记缺口，另批长片验证预算，不能测完短片就宣称长片通过。

## 7. 拟定验收线（待本计划批准）

以固定样本/720p/现有机器/60Hz为初始条件；P95是95%的请求不超过该值。测试计时终点是画面提交，非物理屏幕刷新。

| 项目 | 拟定标准 |
| --- | --- |
| 输入与光标 | 输入到光标提交P95≤16.7ms，最长≤50ms；任何等待不回跳、不锁UI |
| 代理未就绪的原片 | 同轨迹响应不比同宿主普通播放参考慢20%以上；记录所有空白等待，后台开启相对关闭P95退化≤20%；不可保证任意原片冷跳200ms |
| 整片代理就绪、磁盘冷读 | 准确目标P95≤80ms，最长≤250ms；固定快拖新图间隔P95≤50ms、最长≤100ms |
| RAM已命中 | 准确图P95≤16.7ms；无跨源/旧目标覆盖 |
| 慢拖/逐帧/标注 | 代理就绪后逐帧P95≤50ms；正确源帧率100%，零错误保存，VFR映射不漂移 |
| 自动生成 | 无需拖动，从0推进至100%；持续拖动不重启/回退；状态明确；固定样本整片生成目标≤视频时长，CPU/GPU各报实际，不承诺GPU永远快 |
| 切源/代理接管 | 同一源PTS，帧身份/标注不变；无黑闪或位置跳变；连续播放音画偏差≤1帧且≤40ms |
| 生命周期 | 至少50次打开/拖动/切设置/关闭组合，0次124/解码超时/死锁；可见关窗≤100ms，后台正常退出≤2秒；保留草稿保护 |
| 资源 | 遵守RAM/磁盘额度，GPU纹理与中转计量；反复30分钟操作无持续累积，关闭无自有残留进程/未归还文件句柄 |

不承诺“无论任何设备、画质、拖动速度都绝对流畅”。以上达不到就报告差距和架构瓶颈；不得通过延长超时、只测RAM热命中、降低未获批画质或再增加补位层掩盖。
