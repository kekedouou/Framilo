# E44 加载闪黑与末段校验修复

2026-10-28，关联R-02/R-03/R-08、P-01/P-02/P-04。用户体验反馈：加载画面闪黑，整片生成99%后长时间停顿。本轮是已授权原生链路的小范围修复，不变编码画质、磁盘/RAM额度或冻结发行包。性能验证需要：涉及绘制可见性和代理完整校验。

## 事实与用户决定

- native-player每次JS RAM未命中立即把主画布visibility设hidden，新帧确认才恢复；即使代理请求只有十几毫秒，也可能跨一次刷新造成闪黑。主画布/WebGL/CPU backing均已按尺寸变化更新，未发现每次重复清尺寸的主因。
- whole-proxy编码时间进度封顶99%，之后串行执行整片ffprobe实际解码、源SHA、代理SHA、文件同步/发布。UI只显示stage/progress，隐藏了具体status/message，还沿用编码末尾的剩余时间。
- **用户明确接受等待时保留上一张准确画面，新帧确认再替换；光标继续移动，等待中禁止基于旧画面保存标注。** 此决定替代原计划“未就绪暂空”，不改变源帧身份/准确性。

## 实施边界与验证

1. 只在新源第一次准确出图前隐藏；同源seek保留已确认画面。实际frameId/time不改成新目标，targetTime独立；新增frameHeld表示等待/失败保留，成功准确提交才解除。拒绝迟到结果和跨源残留；标注/圈画及历史单帧导出在held时不能固定旧画面。
2. 末段校验保留全帧数量、实际解码PTS/独立帧/尺寸、源和代理SHA、文件身份及原子发布。尝试完整GPU解码核验，明确关闭硬解时走CPU；不可用时一次回退完整CPU核验，不以container标志替代解码。
3. 显示真实阶段：逐帧核验、源文件校验、代理文件校验、发布；按本阶段真实帧数/字节数更新，不编造总体百分比或剩余秒数。发布/接管含义分开。
4. 只读使用已有固定样本与已完成627MB代理，不重生媒体，不碰正式cache或素材标注。独立验证预算仍≤2GiB/单轮≤10分钟；退出/取消/读写中断、全部写入读取端与旧记录兼容列入模型验证。
