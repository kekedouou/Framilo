记录52.793秒、1846次输入；688次提交、3次同帧复用、1155次被后续输入替代，无错误、无截断。软事件容量达到16000后排空并正常结束，未丢失事件。完成操作P50 5.3ms、P95 27.8ms，最大2421.5ms；7次超过1秒，不能用大部分RAM命中掩盖长停顿。10段拖动中最长无新画面约2843.7ms。

## GPU路径已确认的问题与未知项

1. long-media每个短段重新启动FFmpeg。GPU使用CUDA源解码/缩放和NVENC编码，但每段仍重新初始化、从源关键帧前滚、等待段内图像/音频及安全发布完成。当前“常驻解码器”指播放解码器，不是代理生产器。
2. 同源已有40份720p GPU段清单的生产里程碑：启动至首源帧中位数约1075ms、首编码包1129.7ms、整段处理/发布1932.5ms。末段/特殊段长度不同，且这些清单不全在录制区间生成；仅作诊断，不能当固定每两秒吞吐，更不能称约1秒全部是CUDA初始化或纯编码。里程碑相互重叠，不能相加。
3. Player最多两项图像任务。过时读/准备尚未收尾时仍占槽，新目标可能等待；原生解码资源又不能假释放。segment-reader有异段取消，但不能保证前台立即获得图像槽/工作线程服务。需要区分读、准备、原生解码三个阶段并量到阻塞任务，而非只增加并发或延长超时。
4. CPU的CRF20和GPU的QP20不是等质量/等码率对照。此前固定样本GPU约2.6倍体积，读写校验负担不同；本次没有同源CPU对照，不能称显卡算力比CPU差。格式仍为全帧内H.264，不先更换HEVC/ProRes或降低正式画质。

NVIDIA官方也明确指出，小块视频的独立FFmpeg进程初始化开销会明显影响GPU转码。共享上下文/摊薄初始化是公开方向，但不证明本项目里每一毫秒的归因：[官方FFmpeg指南](https://docs.nvidia.com/video-technologies/video-codec-sdk/13.1/ffmpeg-with-nvidia-gpu/index.html)。本机旧FFmpeg不能因引用新版文档直接假定支持全部新接口。

## 低清切回偏帧与关窗黑屏

低清27次提交中最大目标时间偏差约453.9ms，另一次270.8ms。quick-preview快拖按80/200ms量化请求，接受有限近邻；finish对请求本身有250ms宽限，松手也沿用此宽限。此外8ms回退使用video.currentTime而不是实际视频帧时间，不能保证像素身份。准确代理帧按源PTS显示，所以切回时可能跨帧。这证明临时图时间并未严格对齐，不证明准确代理本身错误。后续需验证同一目标的临时/准确图像，而非只比较currentTime。

关闭先销毁UI并挂黑遮盖，再串行等待监测保存、session回收、后台owner/子进程与租约释放。黑窗等待是现有顺序带来的可见结果；本次体验记录没有关闭阶段事件，尚无法归因几秒分别花在何处。需要分阶段计时及提前停止后台；不能直接强杀或解除原始写入保护来伪造快速退出。

## 下一步实施顺序和验收

1. 自动测试成为每轮交付门槛：复用已有脚本，锁定源SHA/画质/CPU或GPU/解码偏好/驱动/初始缓存/轨迹/次数；新增统一冷区协议，分未代理、已代理不在RAM、RAM命中三组。当前独立入口已存在，但未形成每轮优化自动执行和报告的完整门槛。人工标测保留；独立Chrome与真实Eagle分开分组，不伪称宿主自动化已打通。
2. 报告首屏优先列未代理跳转的首张临时图、准确目标帧、松手延迟、最长无新画面及慢请求数，分别展示中位数/P95/最大值、取消与错误。固定CPU/GPU同画质与相近质量/体积对照分开；自动报告事实并由Codex补分析，不让用户手工填表。
3. 先改前台调度：最新目标优先，停止过时准备和投机工作；保留真实取消/收尾屏障，有界释放逻辑槽，不释放仍被原生解码占用的内存。测到具体阻塞任务/阶段，减少取消后重启同一区域的浪费。
4. 再优化生产链：试验常驻生产器复用CUDA/解码/编码上下文，前台可抢占，优先交付已校验目标帧，再完成其余段和音频。此项涉及发布及持久兼容边界，先隔离证明帧身份、取消、重开和旧缓存读写闭环，再接正式。仅扩大段长会恶化远跳，不能当成解决方案。编码配方比较呈现画质/体积代价，未经取舍不替换默认。
5. 低清和准确图绑定同一源帧索引；拖动可有明确近似预览，松手后转为同目标低清，只接受可确认帧时间，淘汰过期结果。验证高动作内容/可变帧率/反向拖动，区分允许抽帧与松手后错帧；临时图永不用于标注。
6. 关窗先处理未保存保护，再立即取消后台/读请求；可独立的监测收尾并行，确认安全接管后隐藏窗口，后台完成有界清理。隐藏失败/清理失败须可报告；重新打开不得继承旧资源。报告分别记窗口消失时间与实际释放完成时间，不能只遮黑或隐藏后宣称性能改善。

第一轮目标：零错误/错帧/光标回跳；冷区准确帧P95相对同条件基线至少减半，低清首图P95目标200ms内；达到不了就保留真实落差。关窗窗口响应目标200ms内，真实清理另测且有界；CPU/GPU选择以端到端首图和准确帧为准，不以编码fps单项决策。阈值为待验证目标，不是达标声明。新协议/生产器实验使用独立有界目录与预算，不复用已经消费的E41媒体额度。
