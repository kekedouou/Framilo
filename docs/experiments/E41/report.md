## 实测条件及结果

同一只读“流放之路”：SHA256 `c6e025b647bf733411779212b8a99580b5bfc012a14c8e974720234877513f8f`，AV1 1920×1080 / 328.6094375 秒 / 9858 帧；720p，10GiB，i7-12700H / RTX 3060 Laptop / FFmpeg 6.1。真实 guard/task-client/FFmpeg 和正式 Player/WebCodecs，在独立 Chrome 测软件绘制提交。浏览器链未测声音；不替代 Eagle。

修改前、最终 CPU、GPU 各三轮，六个初始无代理目标：84.6、257.2、28.4、303.4、158.8、328.4 秒。每轮先测冷区，重建空 RAM Player 测同目标磁盘读取，再三次热 RAM；阻止闲时填充控制起点。生成进度、正确源帧、请求和代码条件保留。GPU 三轮后对最终快速跟随另补一轮；不得把补测当三轮最终跟随证据。

| --- | ---: | ---: | ---: |
| 冷区准确帧，中位数 / P95（各18次） | 936 / 1231 ms | 895 / 1020 ms | 1081 / 1415 ms |
| 冷区第一张临时图，中位数 / P95（各18次） | 无，0/18补位 | 178 / 214 ms，18/18 | 179 / 207 ms，18/18 |

最近秩 P95 在18样本时等于最大值，样本不足以声称统计显著。CPU 临时图 P95 超目标200ms约14ms；准确帧 P95下降约17%，未达到减半。不能把临时图当准确帧、把中位数当尾延迟、把独立 Chrome 与用户 Eagle 6.3ms直接算提升。

最终 CPU 固定快拖三轮：24输入/32ms间隔，分别13/14/13张临时图；最大相邻图间隔125/161/117ms；松手准确帧690/458/501ms。GPU补充一轮11张、181ms、444ms。准确源帧无错位。初版过严地只接受完全相同最新目标，快拖只出现2～4张图且有约700ms停顿；已用有界跟随修正，旧诊断保留，不以旧快拖成绩交付。修改前测量器未忠实复现旧 Session 的 release-cancel，因此**不作修改前快拖提升百分比**。

## GPU 代价与没有采用的方案

CPU 使用原 libx264 ultrafast/CRF20；GPU 为 NVENC p1/QP20，全帧内 baseline、无 B 帧。三张同 PTS 样本对720p参考的 PSNR：CPU 41.8～42.4dB，GPU46.5～47.3dB，后者像素误差小，但不等于主观观感全部通过。五段同样2秒样本外推磁盘量：CPU130.6MB/分钟，GPU341.8MB/分钟（约2.6倍，包含音频；并非整片实测）。

另做一次同 CPU 目标码率17.4Mb/s的 GPU VBR 探测：2秒4.87MB（CPU4.35MB），84.6秒单帧43.0dB；纯 FFmpeg 管线463ms，**不含正式发布/音频，不能与端到端数字比较**。仅用来说明码率/质量取舍，不把单段探测作为新默认配方。用户可选当前GPU方案；默认CPU不动，HEVC/ProRes未接入。

本轮未引入常驻生成进程、提前发布单帧或独立360p代理。现有临时路径仍由原视频原生解码后缩小，并未消除原片长 GOP 解码成本。常驻生成和更低分辨率路径仍需针对抢占、帧身份与颜色/资源竞争作后续验证；本轮不能声称计划中的所有性能目标都已完成。已修交互缺口，实测和仍未达到的目标一并交付。
