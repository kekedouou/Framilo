## 目标与批准边界

先修光标、临时预览和记录有效性，再优化代理生产。关联R-01/02/03/04/06/08、P-01～P-04及其后续已批准补充；旧30秒等历史规格不能覆盖当前长视频决定。

触及调度、解码、编码和缓存，**必须进行性能验证**。固定素材为本次“流放之路”，保留当前720p/10GiB/提前解压条件用于热RAM回归；冷区实验另建协议，不能与当前100%RAM命中的成绩直接算提升。

本轮批准接入GPU H.264可选路径，保留CPU H.264和JPEG模式；HEVC、ProRes列为取舍候选，**不随本计划默认批准进入正式版本**。不改变源视频、永久标注、原有JPEG整片准备策略、动效、缓存安全核验或用户资源额度。

## 执行顺序

### 1. 修复交互与生命周期

- 将“用户最新目标”与“实际已显示帧”保持分离。连续画面拖动、时间轴、滚轮和键盘相对移动统一以最新目标为起点，过时结果不能拉回光标；标注仍只绑定已确认的准确源帧。
- 关闭过程中维持当前黑色界面至宿主窗口真正关闭；资源回收不再把旧布局恢复到可见页面。保留未保存内容保护、关闭失败提示与重新打开能力。
- 仅移除性能监测子窗口的Eagle原生菜单；保留独立拖动、调整大小和关闭。先验证Eagle/Electron 22允许的窗口接口，不使用影响Eagle主程序的全局菜单修改。

### 2. 让低清预览可靠补位

- 松手、点击跳转后，只要准确帧仍未准备，临时预览继续工作；准确帧真正提交后才退场。
- 请求只追随最新目标，旧位置结果不得覆盖新位置；短暂超时不再永久禁用整段视频的低清。区分正常取消、暂时繁忙、格式不支持与真正解码失败。
- 已有附近小图立即复用，同时请求更接近目标的预览；不能把距离很远的旧帧冒充当前目标。低清状态、来源时间和与目标的偏差进入性能记录。
- 准确帧等待超过约80～100ms时启动补位。比较“优先取目标单帧，不等完整代理段”和独立360p/480p低清路径，后台逐步补充稀疏小图；不新增打开视频前必须完成的整片预览任务。
- 当前原视频video路径只缩小输出，解码成本没有随画布缩小；新路径需计量首图等待及CPU/GPU竞争，避免预览与代理各自无限排队。原片尚无可用数据时不能承诺零延迟。

### 3. 优化代理生产，先不换压缩格式

先细分目标等待：前台排队、进程/解码器初始化、原片关键帧前滚与解码、缩放、编码、发布检查。把可直接测量项与管线重叠/无法细分项区分，不虚构分阶段耗时。

优先验证现有FFmpeg上的原片GPU解码→GPU缩放→H.264 NVENC编码；播放端继续复用常驻解码器。兼容失败时允许CPU路径并记录原因，不能静默改画质或把prefer-hardware写成已验证硬解。

减少每个短段重新启动解码/编码的成本：比较有限寿命的连续生产任务与可抢占的附近批次，目标位置优先、后台顺序补齐；保留已有分段原子发布、租约、源帧PTS、取消和关闭屏障。先验证再确定是否引入常驻生成进程，不预先承诺某个架构已经最快。

设置放在高级中：

- 代理生成：CPU / NVIDIA GPU；初期保留当前默认，用户可切换。
- 播放解码：自动 / 优先GPU / 优先CPU。宿主无法确认实际后端时显示“请求GPU，实际后端未确认”，不能伪报。
- 播放方式继续保留帧内代理 / JPEG序列。编码器变化必须隔离代理配方身份，防止旧缓存误复用；切换等旧任务释放，不重用旧代次结果。

### 4. 只保存、展示完整有效的测试

- 体验采样在事件/字节/请求/时长任一软上限到达前停止接收新操作，保留收尾空间；已有操作结束或按规则超时后自动保存，明确提示“已达到上限，记录已保存”。不再先丢数据再报错。
- 标准测试须跑完固定轨迹；未跑完、证据缺失、被手动输入干扰或截断即作废。测试中测到的慢响应、单次超时或崩溃可以是有效失败结果，前提是协议定义该终态且证据完整；不因成绩差而删除有效测量。
- 作废运行不进入report和待分析索引；提示原因后删除本次未发布记录及临时文件。保存磁盘失败时不冒充成功，保留内存供重试；删除失败明确提示，不能谎称已清理。
- 保持同类最多一份待分析记录与覆盖确认；采用先写临时、校验、再替换指针的事务，不能先删上一份有效记录后发现新记录失败。
- 按本次指定保留ID清理两个性能报告目录中的其它运行及对应副本、旧导入/分析辅助产物；执行前核对归属、引用和内容，生成简短清理回执，不保留被要求删除的整份原始失败数据。
- 重建聚合图表、待分析与组索引，修复文档中直接指向已删除性能文件的入口。历史软件验证证据、素材、正式视频缓存不属于此次批量清理。
- 只有完整有效记录进入report；体验诊断与标准对比分开，正常采样窗口到上限结束可以有效，未完成固定标准不可以。

## 编码方案的代价

以下是候选机制与预期，不是本机速度成绩。全帧内编码意味着每帧独立，不能套用普通长GOP视频的压缩率宣传。

| 候选 | 速度判断 | 画质、占用和接入代价 | 本轮建议 |
| --- | --- | --- | --- |
| CPU H.264全帧内 | 现有libx264 ultrafast基线；生产占CPU，短任务启停仍有成本 | CRF20既有观感；基准保留，非无损 | 保留 |
| GPU H.264全帧内 | 本机可用NVENC候选，端到端加速须实测 | 同格式、接入改动最小；同码率不保证与x264同质量，需比较方块、纹理、发光边缘和颜色；可能用更大码率换质量 | 首先接入为可选路径 |
| GPU HEVC全帧内 | 本机硬件支持；并不保证比GPU H.264更快 | 可能更省空间，但全帧内收益须实测；现有H.264拆包、解码和缓存配方需扩展 | 此轮先不接入，用户选择后再试 |
| ProRes 422 Proxy / LT | 适合编辑，不是本机NVENC编码方案 | 体积通常更大、需新增解码接入；Proxy官方1080p/29.97fps约45Mb/s，即0.34GB/分钟，画质档位仍有损 | 不作为首个提速方案 |
| JPEG序列 | 保留已认可整片准备与独立帧访问 | 长片准备和磁盘成本仍在，不能用它保证首次冷区即时响应 | 原样保留 |

RTX 3060 Laptop支持AV1硬件解码，不支持AV1硬件编码；FFmpeg列出av1_nvenc不代表这张显卡能使用。GPU性能可能受源编码、分辨率、关键帧间隔、缩放与显存传输、驱动、并行任务和功耗影响，不先报“快几倍”。

磁盘成本统一实测每分钟代理字节与峰值暂存；便于理解的换算是码率20Mb/s约150MB/分钟，40Mb/s约300MB/分钟，不能把示例当成预计H.264必需码率。CPU/GPU编码质量参数不是同一标尺，应同时提供同码率对照和接近当前观感的体积/速度对照。

## 验证与交付

固定同一视频、预览尺寸、主机、RAM及操作路线，分别建立三组，不混算：

1. **热RAM**：复用本次ready-review-v3条件，保证已有流畅体验无回退。
2. **代理已就绪、RAM未命中**：单独锁定起始RAM集合，测读取、解码、传输和显示；不能先把整条路线预热进RAM再称冷读。
3. **目标尚无代理**：隔离缓存中锁定初始已生成范围和目标路线，测光标响应、第一张临时图、松手准确帧、最长旧画面停留、代理生产耗时/每分钟体积。后台状态、预览命中与被替代请求也记录，不能只统计少数完成的快请求。

先按原实现留下新的冷区参考，再逐项改动、同条件复测，CPU H.264与GPU H.264各至少三轮。实际Eagle与独立测试分别标记；若不能自动控制Eagle，仅本地数据不得宣布宿主通过，最后合并成一次必要人工体验。

批准的实验目标（不代表已达成、不替换原P标准）：

- 连续目标切换无光标回跳，界面在下一次可用刷新更新；松手准确源帧与标注身份零错误。
- “流放之路”720p冷区首张可用临时图P95≤200ms作为实验目标；准确帧等待单独报告，初期目标较同条件原实现减半。达不到如实给出落差，不能把临时图时间充当准确帧时间。
- 热RAM仍按P-01/P-02验收，并与本次6.3ms参考核对；冷区、磁盘和RAM不互相代替。持续播放音画、圈画定位、记录缩略图、快速往返、取消/切换/关闭重开全部回归。
- 记录容量终止后无丢失事件，无pending请求残留；固定标准不完整不得进入对比。覆盖失败不损失上一份有效记录。
- 关闭不闪旧UI，监测窗口无Eagle菜单，Eagle主界面不受影响。

批准预算：单素材、单生成任务起步；新媒体临时产物使用新建独立目录、累计≤2GiB，单轮≤10分钟，每个配置最多三轮，超过预算停止并说明。原文件只读、不清正式缓存，不借用旧实验已封存预算；正式运行仍保持用户RAM及5GiB磁盘边界。需要增加候选或预算再列明代价。

影响模块：session/ui/screen-gestures、quick-preview、app/graphite-shell、performance-view/window/core/runtime/runner/report/dashboard/inbox、long-media/proxy-background/proxy-decoder及对应偏好、缓存配方和测试。正式实现前盘点缓存所有读写端与重启/中断兼容，不把UI、Eagle数据或缓存职责合并到入口。

本轮同步product、architecture、development-plan、roadmap、verification、project-profile、progress及性能WORKFLOW正文。实际实现、未采用候选、未达目标、清理和宿主待验见[报告](report.md)与[结果分析](result-analysis.md)；保留原批准目标，不因未达成降低标准。
