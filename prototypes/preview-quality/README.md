Codex显式命令（不要用户代输）：sources.cjs需要已有本机配置及新素材的明确ID；audit.cjs写一份新审计；quality.cjs的参数为素材别名、尺寸、格式、可选capture/full。默认三轮生成，full仅限已登记的≤7秒原生1080p样本；capture保留唯一待验数据，已有指针时拒绝。prepare-host不加载Eagle；smoke-observation仅启动自有观察工具；summarize只读。不得把这些有副作用命令加入默认检查或从文档自动重跑。

界面入口在scratch/host：普通播放仍自动准备整段720p JPEG。点击“所选视频颜色对照”时读取当次Eagle单选；同素材从当前时间附近取样，选择不同则从0秒取样，≤1秒/60帧1080p，无音频。默认右侧优化JPEG候选，左侧直接显示同帧原视频；自动核对少量数值并保存后即可比较，下拉可换原JPEG/PNG，按钮与【/】定位片段帧。两栏等比例适应窗口，不设原尺寸滚动。面板明确名称、源/预览尺寸、取样时间和真实帧数。在Eagle换选后点击“读取Eagle当前选中视频”切换；退出/取消/换片等待核对/Player/生成工具释放及清理，再继续。“返回普通播放器”重新读取Eagle选择。不是完整新产品或整段1080p验收。

“开始内存记录”仅在普通播放器主动开启，每秒记录并显示缓存账目、插件所属进程、媒体处理和记录工具内存；缓存是进程内存的一部分，不能相加。用户正常使用、结束时停止或关闭即可，分析由Codex完成；不要求固定陪测时长。画质面板显示自身缓存RAM，进入时停止普通使用记录，不默认增加系统采样。真实GUI新流程、画质收益及长期趋势仍待用户反馈/真实记录。

原始源指纹与输出/失败/清理回执保存在根verification-runs/evolution-01，不能删除或覆盖来腾空间；scratch也不能递归清空。出现错误先看具体归属/时间/格式与原始记录，不通过调大额度或删除写锁掩盖问题。

记录布局升级保留旧owner.json原件，以policy-v2.json记录新分配；126份记录各≤128KiB加两份≤4KiB控制文件，仍小于16MiB且最多128文件。达到容量后停止新增记录，画面仍可预览；“核对完成但记录未保存”可重试保存暂存结果，不能误称已保存或播放失败。正式视频缓存/素材库不使用此记录分配器。

## 已完成的颜色显示通道对照（2026-10-17）

同一已批准入口，无需重新导入。Eagle选中之前原生1080p山景，打开演进验证后点**“颜色显示通道对照”**，等待首帧就绪。右侧固定同一画布，左侧下拉依次选：①原视频直接显示；②同一原视频经白底乘色的页面合成；③同一画布经视频通道显示候选。只判断②相较①是否变淡、③是否比右侧鲜艳并接近①；不需要开启内存记录、生成预缓存或长时间测试。切换到③前卸载原视频，始终只有一个video元素；回①重新等同一源首帧，若时间不符则明确未成立。②的白底乘色数学上保持颜色，有Chromium108排除普通视频叠加候选的源码依据，但存在特殊路径例外，没有本机route遥测便不能称已确证变路。

自动保存源摘要、真实VideoFrame颜色说明、实际Canvas配置、模式及流回调条件；同面板最多12条小记录，沿原配额，不保存画面/路径/名称。③不经过JPEG/PNG，但captureStream可能RGB→YUV，既不宣称无损，也不将其回调时间当成源视频PTS已验证。API不支持、解码/超时/取消与保存失败分别处理；保存失败不关画面。返回、换片或关闭取消回调/计时器、停止所有自有tracks、清src/srcObject及Canvas，普通720p播放器及发行版不变。本段为当时运行方法；2026-10-18用户另行授权的自动截图及颜色收尾见顶部，③整段性能未验且不接正式实现。

## 此前：无缓存的原视频／画布验证（2026-10-17）

限定结果已取得：用户人工观察“左侧更鲜艳”，109为1080p同源暂停首帧、无编码/像素读回的条件记录，110另存反馈，不改原pending字段。无需重做这次目视；确认差异可无图片压缩出现，具体显示原因与修复仍待，不能把工具运行成功当颜色通过。下文保留操作方法。

当时工具条为**“原视频／画布验证（无缓存）”**，现已由上方三模式对照替代。该轮读取Eagle当次单选MP4；先释放普通720p播放器和记录，再直接载入原视频，仅等首个真实回调帧并暂停，左视频／右同一帧直接Canvas。不调用FFmpeg、不生成JPEG/PNG或图片缓存；条件记录与人工反馈分开。

先选此前原生1920×1080山景，避免缩放；两栏同背景同尺寸，均无调色滤镜。更大源右侧最多1080p，界面明确缩小/辅助；小源不放大内部像素。不播放、不做任意寻帧，首帧黑屏时更换可见首帧的视频。支持≤30秒、4K及以下；换选后点“读取Eagle当前选中视频”。记录实际mediaTime/尺寸/源SHA/环境及人工待定，不保存画面或完整路径，不另开内存观察。返回/换片/关闭释放video和Canvas；读取失败/超时未成立，保存失败不关闭画面。

只需告诉Codex左侧更鲜艳、两边接近或无法判断。此结果用于区分无缓存的显示差异与缓存路径，不独自证明GPU/驱动/ICC根因；不重做拖动或长期测量。原“所选视频颜色对照”仍保留历史JPEG/PNG诊断，当前不要混淆两个按钮。

## 此前颜色修复与JPEG候选（2026-10-17）

用户决定不开发整段无损；PNG仅保留作为颜色诊断参考。正式media与本工具共用已修正的RGB转换；已发布Beta2不改。源缺失矩阵时依Chromium108推断，明确声明的矩阵/范围优先；RGB转JPEG明确用601全范围，画布为sRGB。广色域/HDR不因此通过。

用户确认关闭后刷新同一入口，无需重新导入。普通播放器仍720p、q3/4:2:0 JPEG，旧颜色缓存仅按已有所有权/清单/指纹及占用规则安全重建；未知或在用保留。最后优化JPEG候选为q1/4:4:4，仍有损，正式默认尚未采用。参考视频在回调确认实际时间前隐藏，快速离开再回旧帧不复用过期状态。默认自动比较首/中/末三个源帧：同一浏览器视频Canvas→PNG/原JPEG/优化JPEG的像素统计，数值不是Eagle最终合成或显示器颜色真值。左侧直接视频用于目视，不把PNG无损保存当源颜色已准确。后台只保存小数值/摘要，不存画面/路径/名称或开启长期观察。

自动核对完成后默认不要求点击测试按钮；“重新核对颜色”仅供必要重试，记录失败保留待存结果、未知写入交Codex核对，不重新取样覆盖。解码失败、帧时间未对齐和保存失败分别提示；取消勾选/关闭释放参考视频、回调、位图与当前自有输出。集中看两段有代表素材即可，不重复拖动/长期验收。成本、Node16实际后端与用户颜色待验收边界见Evolution报告最新节。

新增color-check.cjs：显式指定用户批准名称，一次最多两项、各两帧/720p和1080p，在内存中比较旧/新RGB及JPEG与独立YUV公式，不写测试媒体；写一份有界证据。native-reference.cjs仅用于实验同帧参考，不进入正式插件。
